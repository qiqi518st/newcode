# MewCode Agent Loop — 需求规格 (spec.md)

## 背景

MewCode 是一个终端 AI 编程助手（类似 Claude Code）。ch03 已完成工具系统，模型能调用六个核心工具来观察和操作项目，但每次只能做一步——模型返回一个 `tool_use`，Agent 执行后回灌，再调一次模型获取最终文本答复即结束。ch03 明确把 "Agent Loop / 多工具连环调用 / 自动循环判断" 列在"不做的事"中。

ch04 的目标是用 ReAct 循环引擎**替代** ch03 的单轮闭环。装上 Agent Loop 后，MewCode 能自主循环——先想，再调工具，看结果，边做边调整，直到任务完成。从被动应答变成真正能自主干活的 Agent。

## 目标

- 用 ReAct 模式循环**替代** ch03 的单轮闭环：一轮轮调 LLM、执行工具、结果回写，直到模型不再要工具
- 提供多种停止条件确保可控：模型说完、迭代上限、用户取消、连续未知工具、流出错，迭代上限是兜底安全网
- 建立一套异步事件流，让 Agent 和界面彻底解耦
- 流式收集器走双路：一边实时把文本推给界面，一边攒出完整响应供循环终止判断
- 一次返回多个工具调用时按安全性分批，能并发的并发跑，有副作用的串行跑
- 实现 Plan Mode 两段式：`/plan` 只放开只读工具让模型先出计划，`/do` 切回全工具执行
- 对话历史在正常路径和异常路径下均保持合法，会话可继续
- 实时展示迭代进度和 Token 用量，让用户感知 Agent 的多轮推进过程

## 功能需求

### F1: ReAct 循环引擎（替代 ch03 单轮闭环）

Agent 采用 ReAct 模式循环**替代** ch03 的单轮闭环（请求#1(带工具)→执行→回灌→请求#2(续答)→停）。

核心循环逻辑：每次迭代向 LLM 发起请求（携带工具定义），消费流式响应，收集完整文本和工具调用列表。如果模型返回了工具调用，执行它们并将结果回灌对话历史，进入下一轮迭代。如果模型只返回文本（无工具调用），循环终止，本轮 Agent 运行结束。

与 ch03 的关键区别：ch03 只处理一个工具调用后就结束；ch04 的 ReAct 循环会持续迭代直到满足某个停止条件，可处理任意数量的工具调用。

循环的每次迭代称为一个 turn，Agent 内部维护一个 turn 计数器。达到迭代上限时强制终止，迭代上限为内置常量（默认 10），本章不通过配置调整。

### F2: 多种停止条件

Agent Loop 在以下任一条件满足时停止：

- **F2a: 自然终止** — 模型在流式响应中只产出文本，未产出任何工具调用。这是正常完成路径。

- **F2b: 迭代上限** — turn 计数器达到内置上限（默认 10）。终止前将"达到迭代上限"的提示回灌对话历史，让模型给出阶段性总结。

- **F2c: 用户取消** — 用户在流式态下按 ESC 或 Ctrl+C 中断当前 Loop：
  - 停止后续迭代，不执行尚未开始的工具调用。
  - 回到空闲态，**不退出程序**。
  - 空闲态下再按 Ctrl+C 或 ESC 才退出程序。
  - 中断后对话历史保持合法（见 F8），用户可继续对话。

- **F2d: 连续未知工具** — 模型连续请求的工具在注册表中找不到。连续 2 次出现未知工具时停止，避免模型反复调用不存在的工具造成死循环。

- **F2e: 流式错误** — Provider 流式响应中发生错误（网络错误、API 错误等）。停止本轮迭代，向用户提示错误信息，**不崩溃、不中断会话**。用户可继续下一轮对话。

所有停止条件终止循环后，Agent 都产出终止原因，供 UI 展示或日志记录。

### F3: 统一异步事件流

Agent 通过 `AsyncIterator[Event]` 对外暴露事件流，事件类型扩展为：

| 事件类型 | 携带数据 | 说明 |
|---------|---------|------|
| `TEXT` | `str` | 文本增量，逐 token 推送 |
| `TOOL_CALL` | `ToolCall` | 单个工具调用请求（参数已解析完整） |
| `TOOL_RESULT` | `ToolResult` | 单个工具执行结果 |
| `TOKEN_USAGE` | `TokenUsage` | 每次 LLM API 调用完成后推送 input/output token 数 |
| `TURN_START` | `int` | 新一轮迭代开始，携带当前 turn 编号 |
| `TURN_END` | `TurnEnd` | 一轮迭代结束，携带 turn 编号、该轮工具调用数、该轮 token 用量 |
| `DONE` | `StopReason` | Agent 运行结束，携带终止原因 |
| `ERROR` | `Exception` | 不可恢复的错误 |

`TokenUsage` 包含 `input_tokens: int` 和 `output_tokens: int`，每次 API 调用后推送一次。UI 负责跨轮累加为会话累计量。

`TurnEnd` 包含 `turn: int`、`tool_call_count: int`、`token_usage: TokenUsage`，标记一轮迭代的边界。

`StopReason` 是枚举：`NATURAL`（自然终止）、`MAX_TURNS`（达到上限）、`CANCELLED`（用户取消）、`CONSECUTIVE_UNKNOWN_TOOLS`（连续未知工具）、`STREAM_ERROR`（流出错）。

### F4: 流式收集器（StreamCollector）

在每次 LLM API 调用中，流式响应同时走两条路径：

- **实时路径**：`text` 增量通过 `TEXT` 事件实时推送给 UI，不等待完整响应。
- **累积路径**：`StreamCollector` 内部缓冲所有 `text` 增量，拼接成完整响应文本；同时收集所有 `tool_call` 对象。

一轮流式响应结束后，`StreamCollector` 产出本轮结果：`full_text: str` 和 `tool_calls: list[ToolCall]`。Agent 据此判断：如果 `tool_calls` 非空，继续循环执行工具；如果只有 `full_text` 无工具调用，自然终止。

`StreamCollector` 还负责处理 `thinking` / `reasoning` 内容：思考内容不推送给 UI，不进入累积文本，仅内部丢弃。

### F5: 工具调度器（ToolScheduler）

当一轮迭代中模型返回多个工具调用时，`ToolScheduler` 负责按安全性分批调度：

- 读取每个工具注册的 `is_read_only` 属性。
- 所有 `is_read_only=True` 的工具归入**并发组**，通过 `asyncio.gather` 并行执行。
- 所有 `is_read_only=False` 的工具归入**串行组**，按模型返回的顺序逐个执行（有副作用的工具可能存在依赖关系）。
- 执行顺序：先并发执行只读组，再串行执行读写组。如果只读组中某个工具失败，不影响同组其他工具；读写组中某个工具失败，后续串行工具仍继续执行。
- 所有工具执行完毕后，结果（成功和失败）汇总，按模型返回的原始顺序回灌对话历史。

### F6: Tool 协议扩展

在现有 Tool 协议上新增 `is_read_only` 属性：

- `is_read_only: bool` — 声明工具是否为只读操作。只读工具可并发执行，有副作用的工具需串行执行。
- 现有六个工具分类：`read_file`、`list_files`、`search_code` 标记为 `True`；`write_file`、`edit_file`、`execute_command` 标记为 `False`。

此属性为 `ToolScheduler` 提供调度依据。

### F7: Plan Mode 两段式

Plan Mode 是 Agent 的一种受限运行模式，`/plan` 和 `/do` 为简单手动切换，不引入计划审批工具或计划持久化。

**阶段一 — `/plan`（计划模式）：**
- 用户通过斜杠命令 `/plan`、快捷键或配置文件 `defaultMode: "plan"` 进入计划模式。
- 计划模式下，Agent 只注册只读工具（`read_file`、`list_files`、`search_code`），不注册读写工具。
- 模型可以探查代码、理解项目结构，但无法修改任何文件或执行命令。
- 模型产出计划文本后，Agent 将计划写入指定文件（默认 `plan.md`，路径可配置）。
- 计划模式下的对话历史不保留到执行阶段（两个阶段是独立的 Agent 运行）。

**阶段二 — `/do`（执行模式）：**
- 用户 review 计划文件后，通过 `/do`、快捷键或直接输入 Build 指令进入执行模式。
- 系统读取计划文件内容，注入到新的对话上下文（作为 system prompt 的补充或首条 user 消息的上下文）。
- Agent 恢复全工具集（六个工具），正常执行 Agent Loop。
- 执行阶段的对话历史独立管理，不与计划阶段混淆。

**默认模式配置：** 配置文件支持 `defaultMode` 字段，取值 `"plan"` 或 `"normal"`。设为 `"plan"` 时，启动后默认进入计划模式，所有工具调用受限。

### F8: 对话历史完整性

**正常路径：** 一轮迭代中，模型的 assistant 消息（含文本和/或多个 `tool_calls`）与对应的 tool 结果消息按序写入对话历史。当一轮迭代包含多个工具调用时，assistant 消息携带多个 `tool_calls`，随后依次追加对应的 tool 结果消息。

**异常路径：** 取消 / 上限 / 未知工具 / 出错后，对话历史保持合法——工具调用与结果配对不破、角色交替不破、会话可继续。被取消时，已发起但未完成的工具调用补「已取消」结构化结果，防止出现"有 tool_call 无 tool_result"的脏历史。上限 / 未知工具 / 出错终止时，当前轮的工具调用与结果已正常写入，后续迭代不再发起，历史保持完整。

滑动窗口逻辑保持不变：按 user/assistant 对数裁剪，tool 消息不计入对数统计。

### F9: Token 用量统计

- 从 Provider 流式响应中提取每轮 LLM API 调用的 token 用量（输入 / 输出）。
- 通过 `TOKEN_USAGE` 事件推送给 UI。
- UI 跨轮累加为会话累计量，在状态栏展示。

### F10: 迭代进度展示

- 流式态动态区展示当前迭代轮次（如 "Turn 3/10"），让用户感知 Agent 正在多轮推进。
- 通过 `TURN_START` 事件携带的 turn 编号驱动 UI 更新。

### F11: 配置扩展

`ProviderConfig` 或顶层 `Config` 新增以下可配置项：

- `plan_file: str` — Plan Mode 输出的计划文件路径，默认 `plan.md`。
- `default_mode: str` — 默认运行模式，取值 `"normal"` 或 `"plan"`，默认 `"normal"`。

## 非功能需求

### N1: 循环可控
每次迭代有明确的 turn 计数器，达到上限强制终止。用户可随时取消（ESC 或 Ctrl+C），Agent 在流式态下立即停止循环回到空闲态，不退出程序。空闲态下 Ctrl+C 退出程序。不会出现无限循环或无法中断的情况。

### N2: 界面不阻塞
Agent Loop 期间界面保持响应。工具执行通过 asyncio 并发，不阻塞事件循环。流式文本实时推送，用户可看到 Agent 的思考过程。ESC 和 Ctrl+C 取消信号在事件循环中即时生效。

### N3: 错误隔离
单次工具调用失败不影响同轮其他工具，不影响后续迭代。网络错误可重试（沿用 ch02 的重试机制），重试失败后以 `STREAM_ERROR` 终止，不崩溃、不中断会话。任何错误不导致程序崩溃或会话丢失。

### N4: 内存可控
对话历史通过滑动窗口控制（沿用 ch02），不因 Agent Loop 多轮迭代而无限增长。`StreamCollector` 的缓冲区在每轮迭代结束后清空，不跨轮累积。

### N5: 与现有架构兼容
Agent Loop 作为 Agent 模块的内部升级，不改 `Provider` 协议、不改 `ConversationManager` 核心接口、不改 TUI 状态机结构。TUI 只消费新增的事件类型，不需要改动状态机核心逻辑。

### N6: 调度安全性
工具调度器不改变工具执行的语义——每个工具的执行环境和参数与单独调用时完全一致。并发执行只读工具时，各工具之间互不干扰。串行执行读写工具时，遵循模型返回的原始顺序。

### N7: 可观测性
每个 turn 的边界通过 `TURN_START` / `TURN_END` 事件明确标记。Token 用量每次 API 调用后推送，跨轮累加在状态栏展示。当前迭代轮次在流式态动态区展示。终止原因通过 `DONE` 事件的 `StopReason` 明确标识。所有事件可被日志系统记录，便于调试和监控。

### N8: 跨协议一致
Agent Loop 的行为在 Anthropic 和 OpenAI 两种协议下一致。`StreamCollector` 内部处理两种协议的工具调用格式差异，对外产出统一的 `ToolCall` 列表。循环终止条件、事件流、调度策略均不依赖具体协议。

### N9: 密钥安全
API 密钥不回显到对话区或任何输出中（沿用 ch03 N11）。

### N10: 结果体量受控
工具结果沿用 ch03 工具级截断（行 / 字符上限 + `[truncated]` 标记）。多轮累积下上下文与界面均不被撑爆。

### N11: 工具执行超时
每个工具执行仍受 per-tool 超时约束（沿用 ch03 规则，不可配）。超时以结构化结果回灌，不中断循环。

### N12: 并发安全
并发批内的工具执行与结果收集无数据竞争。asyncio 单线程模型下确保 `await` 切换点不破坏共享状态；并发执行使用 `asyncio.gather`，各工具写入独立下标。

## 不做的事

- **权限系统**：工具执行不做授权确认，不做用户交互式确认弹窗。白名单仍是唯一安全机制。留给后续章节。
- **上下文压缩**：不做对话历史的智能压缩、摘要或结构化裁剪。滑动窗口是唯一裁剪机制。留给后续章节。
- **工具调用中断/取消单个工具**：用户取消是取消整个 Agent 运行，不支持取消单个正在执行的工具。
- **交互式命令执行**：命令执行仍是批量的，不支持 `vim`、`nano` 等交互式 TUI 程序（沿用 ch03 限制）。
- **网络请求工具**：不新增 HTTP 调用等网络工具，ch04 聚焦 Agent Loop 本身。
- **配置化工具集 / 自定义工具**：工具集仍固定为六个核心工具，不支持运行时增删（沿用 ch03 限制）。
- **工具调用与结果持久化**：工具调用与结果不落盘，退出即丢（沿用 ch03 限制）。
- **Plan Mode 的对话历史复用**：计划模式和执行模式是两次独立的 Agent 运行，不共享对话历史。
- **Plan Mode 的计划落盘 / 审批门工具**：`/plan`、`/do` 为简单手动切换，不引入计划审批工具（如 `ExitPlanMode`）或计划持久化机制。
- **工具执行沙箱 / 路径白名单**：沿用 ch03，只允许白名单工具且只能在工作目录内操作。
- **迭代上限 / 超时配置化**：迭代上限和工具超时均为内置常量，本章不通过配置调整。
- **跨批重排并发**：只在「连续只读」批内并发；不把读写调用重排以追求最大并行度。
- **子 Agent / 任务分解工具**：不引入 Task 工具或子 Agent 委托机制。
- **Token 预算限制 / 按用量自动停止**：只统计与展示用量，不按预算自动截断。
- **多模态**：工具结果与对话均为文本。
- **流式工具结果**：工具结果一次性回灌，不做流式产出。

## 验收标准

- **AC1（ReAct 循环替代单轮）**: 用户输入"读取 main.py 和 mewcode/agent/agent.py，对比两个文件的导入部分，然后创建一个 analysis.md 记录对比结果"，Agent 自动进行多轮工具调用（如 list_files → read_file ×2 → write_file），无需用户逐轮确认。TUI 中可见多轮工具调用行，与 ch03 的单工具调用后即停止行为明显不同。

- **AC2（自然终止）**: 用户输入"1+1 等于几"，模型直接回答文本，不调用工具，Agent 循环正常终止。无工具调用行出现。

- **AC3（迭代上限）**: 内置迭代上限为 10。用户输入一个需大量步骤的任务，Agent 在第 10 轮后强制终止，TUI 显示"达到迭代上限"提示，模型给出阶段性总结。对话历史保持合法，用户可继续下一轮对话。

- **AC4（用户取消 — 流式态）**: Agent 执行多轮工具调用时，用户按 ESC 或 Ctrl+C，Agent 立即停止后续迭代，回到空闲态，不退出程序。TUI 显示取消提示。

- **AC5（用户取消 — 空闲态）**: 空闲态下按 Ctrl+C 或 ESC，程序退出。

- **AC6（取消后历史合法）**: 用户取消后，对话历史中已发起但未完成的工具调用已补「已取消」结构化结果，工具调用与结果配对完整。用户可以立即输入新问题继续对话，不会因历史不完整而失败。

- **AC7（多工具并发 — 只读）**: 用户输入"同时读取 main.py、agent.py、app.py"，模型一次返回多个 `read_file` 调用，TUI 中多个工具调用行几乎同时出现（并发执行），而非逐个串行。

- **AC8（多工具串行 — 读写）**: 模型同时返回 `write_file` 和 `edit_file` 调用，工具按顺序执行（先 write_file 再 edit_file），TUI 中工具调用行按顺序出现。

- **AC9（连续未知工具停止）**: 注册表中移除某个工具，模型连续 2 次请求该工具，Agent 以 `CONSECUTIVE_UNKNOWN_TOOLS` 终止。对话历史保持合法，用户可继续对话。

- **AC10（流式错误不崩溃）**: Provider 流式响应中发生网络错误，Agent 以 `STREAM_ERROR` 终止，TUI 显示错误提示，程序不崩溃，会话不中断，用户可继续下一轮对话。

- **AC11（Token 用量事件）**: Agent 运行中，每次 LLM API 调用后能观察到 `TOKEN_USAGE` 事件，包含 input/output token 数。UI 跨轮累加后在状态栏展示会话累计量。

- **AC12（Turn 边界事件）**: 多轮工具调用中，每轮迭代开始和结束都有 `TURN_START` / `TURN_END` 事件标记边界。TUI 流式态动态区显示当前迭代轮次（如 "Turn 2/10"）。

- **AC13（Plan Mode 计划产出）**: 用户输入 `/plan 帮我分析项目结构并给出重构建议`，Agent 只能使用只读工具（read_file、list_files、search_code），无法写文件或执行命令。产出计划写入 `plan.md`。

- **AC14（Plan Mode 执行）**: 用户 review 计划文件后输入 `/do`，Agent 读取 `plan.md` 内容，恢复全工具集，执行计划中的操作。

- **AC15（单次调用模式支持 Agent Loop）**: `mewcode -c "读取所有 py 文件并统计行数"` 能完整走通 Agent Loop（多轮工具调用），终端输出工具行和最终回复后退出。

- **AC16（跨协议一致）**: 使用 Anthropic 和 OpenAI 两种 provider 分别测试相同的多工具任务，Agent Loop 行为一致（循环轮数、事件类型、终止条件均相同）。

- **AC17（密钥安全）**: API 密钥不出现在对话区、工具输出、状态栏或任何输出中。
