# NewCode ch06 — 五层权限系统 需求规格 (spec.md)

## 背景

NewCode 自 ch03 起具备工具调用能力，ch04 引入 Agent Loop（自主循环调用工具、分析结果、再调用工具直到任务完成），ch05 优化了结构化系统提示。Agent 自主性越强，工具调用带来的安全风险越需要正式管控。本章为 NewCode 建立五层纵深防御的权限系统。

现状安全机制薄弱：

- shell 命令仅靠首 token 白名单（固定命令集），无法精细放行，也无法拦截白名单内命令的破坏性用法（如 `git push --force`）
- 文件路径仅做前缀判断，未解析符号链接，项目内符号链接可绕过检查逃逸到外部
- 安全约束主要靠系统提示指令（模型自觉），无代码级强制

ch04 spec 已明确「权限系统留给后续章节」，本章正式接手。

## 目标

- 建立五层权限系统：危险命令黑名单 → 路径沙箱 → 可配置规则引擎 → 多档权限模式 → 人在回路
- 权限检查器串联输出机制：任一层给出终值 Allow/Deny 即短路返回；只有全部未拦且模式判为 Ask 时才落到人在回路
- 判定只有三种中间值 Allow / Deny / Ask，权限模式兜底裁决结果只有 Allow 或 Ask，Deny 只可能来自黑名单、沙箱、显式 deny 规则、人在回路拒绝
- 权限被拒绝时不终止 Agent Loop，拒绝原因回灌模型，让模型有机会调整策略
- 多档权限模式与多层配置：分为 default / acceptEdits / plan / bypassPermissions 四档，按「只读 / 文件写 / 命令执行」三类工具给出 Allow 或 Ask 的兜底裁决；运行时可切换
- 危险操作黑名单：用一组内置正则在执行前拦掉已知高危命令（命令执行类工具），这一层不可被任何配置或模式放开
- 路径沙箱：把文件类工具的读写限定在项目根目录内，先解析符号链接再做前缀判断防止逃逸
- 可配置规则：规则支持用户/项目/本地三层，按「工具名(模式)」声明 allow/deny，支持精确与 glob 匹配
- 人在回路：模式判为 Ask 时暂停 Loop，把决定权交回用户，支持「允许本次 / 永久 / 拒绝本次」三种选择
- 拒绝不中断：任何一层的 Deny 都包成结构化错误结果回灌给模型，Agent Loop 继续往下走
- 跨协议一致：权限判定发生在 agent 编排层，与 Anthropic / OpenAI provider 无关
- 与 ch04.5 的 plan、do 模式整合

## 功能需求

### F1: 权限检查器（串联五层）

系统提供统一的权限检查入口，每次工具调用执行前按固定顺序串联五层防线：

1. 危险命令检测（黑名单）
2. 路径沙箱
3. 规则引擎
4. 权限模式
5. 人在回路（HITL）

任一层给出 Allow/Deny 即短路返回，不再进入后续层。其中黑名单仅对命令执行类工具生效、沙箱仅对文件类工具（读/写/改/搜索）生效；被跳过的层视为「未拦、继续下一层」（如非命令执行工具跳过黑名单后继续走沙箱/规则，命令执行工具跳过沙箱后继续走规则/模式）。只有全部未拦且模式判为 Ask 时才落到人在回路。

判定中间值仅有三种：Allow（放行）/ Deny（拒绝）/ Ask（询问）。权限模式兜底裁决只产 Allow 或 Ask，绝不产 Deny。

### F2: 危险命令黑名单（L1）

用一组内置正则匹配黑名单，在执行前拦截已知高危命令。命中即判 Deny，作为**最高优先级层**，不受任何规则、模式、配置影响——bypassPermissions 模式也拦得住。

覆盖已知高危模式，包括但不限于：递归强制删除根/家目录、写块设备、fork 炸弹、重定向覆盖磁盘设备、格式化文件系统、远程脚本下载即执行（管道到 shell 执行）等。

黑名单是启发式防御而非完备保证，明确不追求穷尽所有危险命令；黑名单内置固定，用户不可增删或关闭。

黑名单替换现有的首 token 白名单机制（白名单命令集不再作为放行依据）。

### F3: 路径沙箱（L2）

文件类工具（读文件、写文件、修改文件、按模式找文件、搜内容）的读写限定在项目根目录内。检查时：

- 将目标路径**规整为绝对路径**
- **先解析符号链接（含 Windows junction）再做前缀判断**，防止通过项目内符号链接逃逸到外部
- 对尚不存在的目标（如新建文件、含未创建的中间目录），解析其**最近的已存在祖先目录**后再判断，不因目标不存在而误判
- 解析顺序固定，防止用软链接指向外部目录绕过

越界即判 Deny，在任何权限模式下都生效。沙箱对读取与写入一视同仁地限制在项目内。

命令执行（Bash）工具不走沙箱——任意命令的文件访问无法可靠静态解析，其危险由黑名单 + 规则 + 模式兜底覆盖。

### F4: 可配置规则引擎（L3）

- 规则格式「工具名(模式)」：如 `Bash(git *)` 表示所有 git 开头的命令
- 工具名使用面向用户的友好名：**Bash / Read / Write / Edit / Glob / Grep**，由引擎映射到对应内置工具
- 每条规则结果只有 allow 或 deny 两种
- 匹配支持精确匹配与 glob 通配（`*` 单层、`**` 递归）
- 对一次工具调用，引擎在给定规则集内判出 allow / deny / 未命中
- 显式规则（allow/deny）优先于权限模式的内建兜底矩阵

> 说明：「询问」不是规则结果，而是「规则未命中且当前模式判为 Ask」时的动作（由 HITL 层承担）。

### F5: 规则分层与优先级（L3）

规则按来源分三层，从高到低：

1. 本地级规则（本地级规则文件，个人本地，不随仓库分发）
2. 项目级规则（项目内规则文件，入库团队共享）
3. 用户级规则（用户全局规则文件，所有项目共享）

跨层查找：从高到低逐层查找，高层命中即定案（无论 allow/deny），不进入更低层。同层内 **deny 优先于 allow**（同层有 deny 命中则判 deny，无视同层 allow）。

特殊情况处理：

- 任一文件缺失视为空规则集（安全降级，不额外放开任何权限）
- 配置文件格式错误绝不导致引擎构造失败，只把该文件降级为空规则集，不崩溃
- 启动时的默认模式取自配置（本地 > 项目 > 用户），未配置则为 default

### F6: 多档权限模式（L4）

四种权限模式，覆盖规则未命中时的兜底裁决。模式只产 **Allow 或 Ask**（绝不产 Deny）：

| 模式 | 只读（Read/Glob/Grep） | 文件写（Write/Edit） | 命令执行（Bash） |
|------|----------------------|---------------------|-----------------|
| default | Allow | Ask | Ask |
| acceptEdits | Allow | Allow | Ask |
| plan | Allow | Ask | Ask |
| bypassPermissions | Allow | Allow | Allow |

- bypassPermissions 跳过规则引擎、权限模式、HITL 三层，不弹任何确认；但**黑名单与路径沙箱仍生效**
- 模式切换只影响后续调用的兜底裁决，不改变已加载规则
- 模式跨轮保持（下一轮对话仍是上次切换的模式，不被重置）
- plan 模式具体行为沿用 ch04.5（见 F9）

### F7: 人在回路 HITL（L5）

判定落到 Ask 时暂停 Agent Loop，向用户呈现待批准的工具调用，用户三选一：

- 界面渲染**多行确认块**：工具名 + 关键参数预览 + 触发原因 + 菜单选项
- 交互方式：**↑↓ 移动光标 + 回车确认，数字键 1/2/3 亦可直选**，默认高亮「允许本次」
- 三个选项：
  - **允许本次** → 判 Allow，不留记录
  - **永久** → 判 Allow，并把对应 **allow 规则写入本地级配置文件**（跨会话生效）
  - **拒绝本次** → 判 Deny（回灌让模型调整）

Agent 发出询问事件后阻塞等待，不继续执行；用户回复后唤醒 Agent，按用户决定执行或拒绝。

### F8: 权限决策反馈（拒绝不终止）

任何一层的 Deny 都包成结构化错误结果回灌给模型，Agent Loop 继续往下走。拒绝原因（含命中的层/规则/模式）清晰可读，模型在下一轮可调整策略。连续权限拒绝不触发循环终止。

### F9: plan 模式整合

- plan 权限矩阵与 default 一致（只读 Allow，文件写/命令执行 Ask）
- 沿用 ch04.5 的 `/plan`（进入）`/do`（执行）作为计划工作流的专用入口/出口，与 Shift+Tab 的 plan 权限模式并存
- plan 模式下向模型暴露全部工具，「自觉只读」由系统提示指令引导；非只读工具的 Ask 兜底为防御性确认框
- 计划文件生成是系统内部动作，不触发权限确认
- 计划完成后保留「是否执行 / not now」交互
- plan 模式下若为单纯询问（无需计划），模型直接对话回复，不生成计划文件、不弹「是否执行」；仅当需要计划时才生成

### F10: 非交互模式权限行为

- 非交互模式（单次调用）默认处于 default 权限
- 需要确认的操作默认拒绝（拒绝原因回灌模型，模型调整策略）
- 提供命令行参数显式指定权限模式，脚本场景可用 bypassPermissions 放行
- 保留非交互 + 计划标志：非交互下直接生成计划文件，不弹「是否执行」，用户后续可用计划执行命令选择执行

### F11: 模式切换与规则文件

- 当前权限模式在**状态栏常驻可见**（占据原 provider 名的位置；不再展示 provider 名）
- 模式切换：Shift+Tab 快捷键在四种模式间循环切换
- 切换只影响后续调用的兜底裁决，不改变已加载规则
- 模式跨轮保持（下一轮对话仍是上次切换的模式，不被重置）
- 既有斜杠命令保留：`/plan`、`/do`、`/normal`、`/delete-plan` 等
- 不新增权限相关的斜杠命令
- 规则文件为 YAML，三层存放（用户/项目/本地），格式一致

## 非功能需求

### N1: 性能
权限检查开销应可忽略：单次工具调用检查在毫秒级，不显著增加 Agent 循环延迟。规则查找短路优先，不扫描全部规则。只读工具的并发执行不因权限检查退化为串行（只读永不触发 Ask）。

### N2: 安全底线
黑名单与路径沙箱是硬防线，任何权限模式（含 bypassPermissions）下都生效，不可被任何规则或模式覆盖。规则 deny 在同层内优先于 allow；高层 deny 覆盖低层一切。

### N3: 规则解析容错
配置文件格式错误（非法 YAML、非法规则语法、未知工具名）绝不导致引擎构造失败：该文件降级为空规则集（不额外放开任何权限），给出明确错误提示，不崩溃、不中断会话。

### N4: 可测试性
权限系统的所有决策逻辑（黑名单匹配、沙箱判断、规则匹配与优先级、模式矩阵、HITL 决策流转）必须可用自动化测试验证，不依赖真实终端或真实 LLM。交互路径用 mock 驱动真实代码路径。

### N5: 跨平台
路径沙箱的符号链接解析需同时支持 Windows（符号链接/junction）与类 Unix；路径比较统一用规范化后的绝对路径，避免大小写/分隔符差异导致误判。

### N6: 向后兼容（不破坏 ch04/ch05）
Agent Loop 多轮编排、流式双路收集、保序分批并发、用户取消、历史一致、缓存与 system-reminder 注入等既有能力不退化。现有工具调用、plan 工作流（进入/执行/删除计划）的行为不因权限系统引入而破坏。未配置任何权限文件时，系统以安全默认行为运行。

### N7: 反馈可理解性
权限拒绝原因应清晰可读（命中的层/规则/模式），既能回灌模型帮助调整策略，也能在界面直观展示给用户。

### N8: 配置确定性
规则分层合并逻辑确定：优先级固定、同层 deny 优先、高层先命中定案，同一配置在任何环境得到一致决策。

### N9: 人在回路可取消、不死锁
等待用户决策期间按 Esc / Ctrl+C 能干净地取消本轮（不泄漏挂起的 asyncio task、不死锁、不退出整个程序）；取消后对话历史角色交替合法、工具调用与结果配对不破坏。

### N10: 跨协议一致
权限判定与 provider 无关，Anthropic 与 OpenAI（含兼容端点）行为完全一致；不改 provider 适配层。

### N11: 安全默认
未知/未注册工具、参数无法解析、类别无法判定等不确定情形，一律按最严处理（按有副作用工具走 Ask、或直接 Deny），绝不静默放行。

### N12: 代码规范
按项目语言的标准格式化 / 静态检查 / 测试命令全部通过（Python：ruff format / ruff check，可选 mypy；遵循 CLAUDE.md）。

### N13: 可扩展性
新增一层防御、一档模式或一类规则匹配时改动局部——不触及判定流水线主编排，不改 provider 适配层。

## 不做的事

- **网络请求限制**：不限制 Agent 发起网络请求，留给后续章节
- **资源用量配额**：不限制 CPU/内存/磁盘等资源用量，留给后续章节
- **审计日志**：不记录权限决策的持久化审计日志，留给后续章节
- **白名单机制恢复**：不保留首 token 白名单作为放行依据（被黑名单 + 规则引擎取代）
- **规则热重载**：规则文件在会话启动时加载，运行中不监听文件变更自动重载
- **黑名单可配置/可扩展**：黑名单内置固定，用户不可增删、不可关闭
- **自动泛化规则**：人在回路「永久」只生成精确匹配规则；通配/前缀规则（如 `Bash(git *)`）需用户手写进配置
- **非内置工具 / MCP 工具的权限**：本章只覆盖 6 个内置工具
- **命令执行（Bash）路径沙箱**：Bash 命令不做路径围栏（无法可靠静态解析任意命令的文件访问），其危险交给黑名单 + 规则 + 模式兜底
- **多项目根 / 额外目录授权**：沙箱只认启动时的单一项目根，不支持运行时追加可访问目录
- **权限规则的图形化 / 交互式编辑器**：规则靠配置文件与人在回路写入，不做规则编辑 UI
- **acceptEdits 之外的细粒度自动批准档**：模式集固定为四档，不做「仅自动批准某工具」之类的自定义档位
- **深层符号链接遍历围栏**：按模式找文件 / 搜内容的目录遍历沿用现有不跟随目录软链接的行为，沙箱只校验其搜索根

## 验收标准

- **AC1（五层串联与短路）**: 黑名单命中 + 规则 allow 的场景，最终决策为 Deny（黑名单短路，不可被规则覆盖）；非命令执行工具跳过黑名单继续走沙箱/规则
- **AC2（黑名单拦截）**: 执行破坏性命令（如递归强制删除系统根、管道远程执行），返回 Deny 并给出黑名单原因；在 bypassPermissions 下仍被拦截
- **AC3（沙箱逃逸防御）**: 项目内创建指向外部目录的符号链接，通过该链接读写文件被拒绝；新建文件的中间目录包含符号链接逃逸被拒绝；普通项目内读写正常
- **AC4（沙箱不存在的目标）**: 新建文件路径含未创建的中间目录，通过最近已存在祖先目录判定落点，不因目标不存在误放行
- **AC5（规则精确/glob）**: `Bash(git status)` 精确匹配；`Bash(git *)` 放行所有 git 命令；`*` 与 `**` 通配按预期匹配
- **AC6（规则优先级）**: 用户级 deny 与项目级 allow 冲突时，项目级 allow 生效（跨层高层优先）；同层内 deny 优先于 allow
- **AC7（规则文件降级）**: 任一规则文件缺失→视为空规则集正常启动；格式非法→降级为空规则集并给出错误提示，不崩溃、不额外放开权限
- **AC8（模式矩阵）**: default 下写文件/命令判 Ask、只读判 Allow；acceptEdits 下编辑判 Allow、命令仍 Ask；bypassPermissions 下全判 Allow 但 L1/L2 仍生效
- **AC9（HITL 三种选择）**: 判 Ask 时弹确认框，默认高亮「允许本次」；↑↓+回车、数字键 1/2/3 均可操作；选「允许本次」仅本次放行；选「永久」写入本地级规则；选「拒绝本次」回灌模型
- **AC10（拒绝不终止）**: 权限 Deny 后 Agent 继续运行，下一轮能看到拒绝原因并调整策略，不触发循环终止
- **AC11（plan 整合）**: plan 模式下写工具/命令调用判 Ask 非直接失败；计划文件生成不弹权限确认；计划完成后「是否执行/not now」正常出现
- **AC12（plan 单纯询问）**: plan 模式下单纯提问（无需计划），仅输出回答，不生成计划文件、不弹「是否执行」
- **AC13（非交互模式）**: `-c` 下判 Ask 的操作被拒绝并回灌原因；`--mode bypassPermissions` 时放行；`-c -p` 生成计划文件且不弹确认；`-c` 下 Esc 无法取消（无 UI）
- **AC14（模式切换）**: Shift+Tab 在四种模式间循环切换；当前模式在状态栏常驻可见；模式跨轮保持不重置
- **AC15（安全底线）**: bypassPermissions 下执行破坏性命令或越界路径仍被拦截（Deny）
