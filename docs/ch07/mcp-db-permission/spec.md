# NewCode ch07 — MCP 对接数据库的权限管理 Spec

## 背景

ch07 的 MCP 客户端已能把远端数据库工具（如 mysql-mcp-server）接进五层权限体系，但有三块缺口（对接真实 mysql-server 实测暴露）：

1. **高危破坏性操作无拦截**：mysql-mcp-server 的 16 个工具全部不声明只读性，配置里若用大权限账号（如 root），agent 可任意执行破坏性 SQL（DROP/TRUNCATE/无 WHERE 的删除）。ch07 明确把「MCP 工具的黑名单扩展」列入不做的事。
2. **agent 不识别远端账号的权限范围**：agent 不知道「该连接账号能访问哪些库/表、能做什么操作」，越权请求（如只读账号调插入/删除）直接发到数据库才被拒，浪费往返并产生噪音。
3. **认证失败风暴**：凭据错误时 agent 反复重试调用，可能触发账号锁定。

数据库侧（MySQL 等）已有完善且强制的权限管理系统：**身份（连接账号）→ 库/表资源 → 具体操作** 的三层授权模型。本功能让 newcode **复用这套远端权限管理**——远端通过权限查询能力暴露当前账号的授权，newcode 据此在调用前提前拦截越权与破坏性操作，并抑制认证失败重试。安全边界由「远端数据库权限（强制执行）+ newcode 预检（提前拦截）」双层构成。

## 目标

- **判定顺序固定**：对数据库型 MCP 工具调用，依次执行 ① 高危操作拦截（先拦黑名单操作）→ ② 资源路径检查（拆出库/表，对授权范围）→ ③ 操作权限检查（该操作是否有对应权限）。与既有五层权限的 L1→L2→L3 顺序一致。
- **复用远端权限管理**：远端通过权限查询能力暴露当前连接账号的授权（可访问的库/表 + 可执行的操作），newcode 把它翻译成预检规则，不重复配置、不写死账号权限。
- **按真实工具形态处理**：数据库 server 的工具分两类——结构化参数工具（如删除/插入/更新，传库表名与条件参数，不传完整 SQL）与自由 SQL 工具（如通用查询，传完整 SQL 文本）。两类的高危检查与资源提取方式不同。
- **动态规则不落盘**：根据当前连接账号生成的预检规则只在内存生效，不写入任何权限文件；换账号/重启后自动按新快照重新生成。
- **LLM 引导**：被禁用的工具不出现在 LLM 可见的工具列表中；账号边界（只读/限库）以提示文案告知 LLM，减少发起注定被拒的调用。
- **认证失败抑制**：凭据异常时停止对该连接的自动重试，防账号锁定，明确告警。
- **不破坏既有能力**：五层权限的既有判定、MCP 既有连接/调用、内置工具行为不退化；未声明权限预检的 server 行为与 ch07 完全一致。

## 功能需求

### F1: 权限预检的配置声明

数据库型 MCP server 在 `mcp_servers` 内通过可选 `permissions` 段声明启用预检，含以下字段（均可选，缺省则该 server 不预检、行为同 ch07）：

- **权限查询工具名**：远端暴露的「查询当前账号权限」工具名（拿权限快照）。
- **自由 SQL 参数名**：该 server 承载完整 SQL 的参数名（用于高危检查 + 资源提取的 SQL 文本解析）。
- **表参数名**：该 server 专用工具承载库表名的参数名（资源提取直取）。
- **危险判定参数名**：专用工具承载条件/过滤条件的参数名（为空 = 无条件全表操作，高危）。
- **工具→所需权限映射（可选）**：覆盖内置映射，供个别 server 定制。

### F2: 权限快照获取

启动时对声明了权限查询工具的 server，调用该工具获取当前连接账号的授权快照，包含：可执行的操作集合、可访问的库集合、每库可访问的表集合、连接默认库、只读标记。快照获取失败（工具缺失/解析失败/调用异常）→ stderr 告警一次并跳过该 server 的预检，不阻断启动、不影响其它 server。

### F3: 判定顺序 ① 高危操作拦截（对应 L1）

对启用预检的 server，工具调用先做高危检查：

- **自由 SQL 工具**：对 SQL 文本匹配内置高危名单（含库表级删除/清空/无条件的删除与更新等），命中 → 直接拒绝（任何权限模式下都生效，含 bypass）。
- **结构化参数工具**：对危险判定参数（如 where）做检查——该参数缺失或为空（= 无条件下全表操作）→ 视为高危拒绝；带明确条件的（如 where 含 id=1）→ 放行进入下一步。
- 高危名单内置、不可配置（对标既有 bash 黑名单的定位）。

### F4: 判定顺序 ② 资源路径检查（对应 L2）

对启用预检的 server，工具调用提取其操作的资源（库/表），与快照授权的资源集合比对，不在授权集合内 → 拒绝：

- **结构化参数工具**：从表参数直接提取 `库.表`（支持 `库.*` 与裸表名，裸表名按连接默认库补全为绝对资源）。
- **自由 SQL 工具**：对 SQL 文本先做规范化清洗（去除注释、字符串字面量、反引号包裹；多语句逐句检测；大小写归一），再提取其中的库表引用。
- **资源边界比对**：提取的资源 ∈ 授权集合（`库.*` 授权通配该库全部表）。
- 任何权限模式下都生效（含 bypass）。

### F5: 判定顺序 ③ 操作权限检查（对应 L3）

对启用预检的 server，工具调用按其工具对应的操作与快照授权比对：

- 内置「工具 → 所需操作」映射（插入工具↔INSERT、更新工具↔UPDATE、删除工具↔DELETE、自由 SQL 工具↔EXECUTE/SELECT、只读类工具↔SELECT/SHOW 等），可用配置覆盖。
- 快照不含该工具所需操作 → 该工具被禁用。
- **禁用的工具不进入 LLM 可见的工具列表**（LLM 不会发起调用）；同时该工具调用被判定层拒绝（安全由判定层兜底，LLM 可见性只是引导）。

### F6: 动态规则生命周期

- 预检规则根据**当前连接账号**生成，只在内存生效，**不写入任何权限文件**（用户手写的三层权限文件内容不受影响）。
- 启动时按当前配置的账号生成；**某次调用被远端拒绝（权限可能已变更）时重新获取该 server 快照并更新规则**。
- 规则按 server 名隔离，互不影响；换账号（改配置）重启后按新快照重新生成。

### F7: 认证失败抑制

- 连接或调用时出现认证失败（如访问被拒 / 凭据错误）→ 标记该 server 凭据异常。
- 标记后该 server 的后续调用直接返回结构化错误，**不再自动重试**；stderr 告警一次（不重复刷屏）；其它 server 不受影响。
- 修复凭据需重启 newcode（配置热加载不在本功能范围）。

### F8: 账号边界提示

对启用预检的 server，把账号边界摘要（如「该连接为只读账号，仅可访问某库」）以提示文案放入会话环境信息，引导 LLM 不生成越权 SQL。**此为引导，安全仍由判定层强制兜底**。

## 非功能需求

- **N1: 顺序恒定**——判定严格按 ① 高危 → ② 资源 → ③ 操作 执行，任一命中即拒绝，不跳过。
- **N2: 安全默认**——快照获取失败/工具无法归类时保守处理（宁可拦，不静默放行）；未声明预检的 server 保持 ch07 原行为。
- **N3: 不落盘**——动态规则与边界提示都不写入权限文件/配置文件，进程结束即消失。
- **N4: 隔离**——单 server 快照失败/认证异常只影响自身，不影响其它 server 与启动。
- **N5: 不破坏既有**——五层权限、MCP 连接/调用、内置工具行为不退化；未预检 server 零差异。
- **N6: 可观测**——高危拦截/资源越界/操作越权/认证异常均给出明确拒绝原因（含 server 名与具体越界内容）。
- **N7: 代码规范**——ruff / pytest 全过（沿用 ch07 的 `@pytest.mark.anyio` 约定）。

## 不做的事

- 权限快照的定时刷新（仅启动时 + 调用失败时）。
- 对非数据库型 MCP server 的高危/资源检查（需要 permissions 声明才启用）。
- 远端权限变更的主动监听（依赖调用失败触发）。
- 修改五层权限的既有判定流程（仅扩展 L1 分支 + L2 资源分支 + 新增 L3 动态注入入口，不改既有规则文件与模式矩阵）。
- SQL 语句级白名单/审计日志。
- 配置热加载（换账号需重启）。
- 逐 SQL 操作的历史审计。

## 验收标准

- **AC1: 配置声明**——`mcp_servers` 内声明 `permissions`（权限查询工具/自由 SQL 参数/表参数/危险判定参数）的 server 启用预检；未声明的 server 行为与 ch07 完全一致。（F1/N2）
- **AC2: 快照获取与降级**——启动时调用权限查询工具拿到授权快照（操作集/库集/表集/默认库/只读标记）；工具缺失或解析失败 → 告警一次 + 跳过该 server 预检，不阻断启动、其它 server 正常。（F2/N4）
- **AC3: 高危拦截**——自由 SQL 工具传入命中高危名单的 SQL（库表级删除/清空/无条件的删除与更新）→ 拒绝；结构化参数工具危险判定参数为空（无 WHERE）→ 拒绝，带明确条件 → 放行；bypass 模式下同样生效。（F3/N1）
- **AC4: 资源边界**——工具访问的库/表不在授权集合 → 拒绝（结构化参数直取 + 自由 SQL 文本规范化后提取两种路径都覆盖）；`库.*` 通配生效；裸表名按默认库补全。（F4/N1）
- **AC5: 操作权限**——工具所需操作不在快照 → 该工具被禁用；禁用工具不出现在 LLM 可见工具列表；判定层对禁用工具调用拒绝。（F5）
- **AC6: 动态规则不落盘**——生成的预检规则只在内存，权限文件内容不受影响；启动时按当前账号重新生成；调用失败触发重新快照后规则更新。（F6/N3）
- **AC7: 认证失败抑制**——认证失败后该 server 后续调用直接结构化错误、不自动重试、告警一次；其它 server 不受影响。（F7/N4）
- **AC8: 边界提示**——启用预检的 server 其账号边界摘要出现在会话环境信息中。（F8）
- **AC9: 不破坏既有**——既有全部测试通过；未声明预检的 MCP server 与内置工具行为不退化。（N5）
- **AC10: 代码规范**——`ruff format --check` / `ruff check` 对 ch07 文件无违规；`pytest`（含新增测试）全过。（N7）
