## 手动测试发现

### 大文件读取与结果落盘

测试命令：

```text
读取 D:\\code\\newcode\\命令.md 中的内容，并将读取结果展示出来，不要自动做内容总结，展示所有内容
```

测试文件实际约 5220 行。一次测试中，`read_file` 使用 `limit=6000` 成功读取完整内容，结果文件大小约 300 KB。随后 ch08 的 L1 大结果管理在下一次发送给 provider 前触发，将完整工具结果保存到会话目录，并把上下文中的工具消息替换为头部预览。

本次测试确认：

- `read_file` 的 `limit` 未传入时默认 500 行。
- `limit` 可以传入大于 500 的正整数，不存在固定的 500 行上限。
- `offset` 可用于继续读取文件的后续部分。
- L1 落盘是上下文管理行为，不是 `read_file` 的读取限制。
- 落盘文件保存原始完整工具结果，模型后续看到的是预览和保存路径。

相关测试会话中的落盘文件：

```text

```

### 提示语混淆

早期提示同时显示默认 500 行和大结果落盘信息，容易让模型误认为 `read_file` 存在 500 行硬上限。最终处理如下：

- `read_file` 截断提示不再显示总行数、行号范围或 `limit` 数值。
- 截断时只显示：`...（本次调用未返回全部文件）`。
- 删除额外的行数限制解释性 TUI 提示。
- 保留 ch08 上下文事件的突出显示：白色、加粗、空心圆 `○` 前缀。
- 大结果落盘、自动压缩、手动压缩和压缩失败仍通过统一上下文事件显示。

## 监控工具测试

测试中只发送了少量用户请求，但监控工具中出现了较多 `Sessions / Requests` 记录。原因是一次用户请求可能触发多轮 agent 处理、工具调用和 provider 请求，监控对象记录的是实际 provider 请求，而不是单纯的用户输入次数。

后续调整包括：

- 使用 `run_id` 聚合同一次用户请求产生的 provider 调用。
- 历史记录缺少新字段时，回退使用 session 和用户输入进行分组。
- 右侧详情支持在同一用户请求的多个 provider 调用之间切换。
- `Latest Provider History` 支持分页查看，避免单页内容超出窗口后无法上下翻动。
- 多个 MewCode 窗口通过不同 session/run 标识区分。
- 打开监控工具时默认定位到最新记录，同时保留手动选择历史记录的能力。

## 其他测试现象

- `stream disconnected before completion: Upstream request failed` 表示上游请求或连接在流式响应完成前断开，属于请求链路异常，不代表本地上下文功能必然失败。
- Anthropic 的 `tool_use` / `tool_result` 400 错误表示消息历史中存在未紧跟对应结果的工具调用块，需要保证每个工具调用都在下一条消息中获得对应的工具结果。
- 权限规则解析曾跳过 `mcp__mysql-server__*`。规则解析器已支持工具名中的通配符，以便匹配 MCP 工具组。
