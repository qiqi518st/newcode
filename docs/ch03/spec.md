# NewCode 工具系统（Tool Use）— 需求规格 (spec.md)

## 背景

NewCode 是一个终端 AI 编程助手（类似 Claude Code）。ch02 已完成 TUI 多轮对话，用户能在终端与 LLM 进行流畅的流式对话。但此时 NewCode 还只是一个"聊天机器人"——模型只能生成文本回复，无法观察和操作真实环境。

ch03 的目标是给 NewCode 装上工具系统。用户提问后，模型能主动调用工具（读文件、写文件、改文件、执行命令、搜索代码等）来观察和理解项目状态，再基于工具返回的结果给出更精准的回答。从"聊天机器人"变成真正能干活的 Agent。

## 目标

- 提供统一的 Tool 接口，每个工具都实现它，元信息带名称、描述、参数 Schema 和执行方法
- 先实现六个核心工具：读文件、写文件、改文件、执行命令、按模式找文件、搜代码内容。每个工具定义清晰的正常返回格式和异常返回格式
- 一个注册中心集中登记工具，按名查找；在每次发起对话请求时，将工具集以 API 要求的格式一并发送给模型
- 工具执行带超时和错误处理，失败信息包成结构化结果返回给模型，让它能调整而不是崩掉
- LLM 客户端要能解析流式的工具调用（JSON 参数碎片拼接），执行完把结果回灌进对话历史
- 改文件走原文唯一匹配替换，匹配不到或匹配多次都给清楚的报错让模型重试
- 支持 Anthropic 和 OpenAI 两种协议的工具调用格式，且跨协议体验一致
- 命令执行工具采用白名单安全策略，仅允许执行预定义的安全命令（以读命令为主，辅以项目范围内的文件追加写相关操作）。本章不做完整的 Agent 权限模块，白名单仅作为防止测试过程中 Agent 误执行高危命令的临时防护
- 工具调用在 TUI 中以 Claude Code 风格工具行呈现（如 `● Read(path)` + 结果摘要），纳入对话历史

## 功能需求

- **F1: 统一 Tool 接口** — 每个工具实现统一的接口，包含：名称、描述、参数 JSON Schema、执行方法。描述和 Schema 直接用于构建 API 请求中的工具定义。

- **F2: 六个核心工具**，每个工具定义正常返回和异常返回：

  - `read_file`：读取指定路径的文本文件内容。
    - 正常返回：文件内容字符串。支持可选行范围（`offset`/`limit`）。
    - 异常返回：文件不存在、路径越界、权限不足、不是文本文件时，返回结构化错误。

  - `write_file`：向指定路径写入文本内容，目录不存在自动创建，文件已存在则覆盖。
    - 正常返回：确认信息（如已写入字节数）。
    - 异常返回：路径越界、目录创建失败、权限不足、磁盘空间不足时，返回结构化错误。

  - `edit_file`：在指定文件中进行原文唯一匹配替换。
    - 正常返回：确认替换成功（如"已替换 1 处"）。
    - 异常返回：文件不存在、`old_string` 未找到、`old_string` 找到多处、替换后写入失败时，返回结构化错误。

  - `execute_command`：在指定工作目录下执行 shell 命令，返回 stdout/stderr/exit_code。
    - 正常返回：stdout、stderr、exit_code。
    - 异常返回：命令不在白名单 → 直接拒绝；超时 → 返回已收集的部分输出 + 超时标记；exit_code 非 0 → 结构化返回（包含 stdout/stderr/exit_code，让模型自行判断）；命令不存在 → 结构化错误。

  - `list_files`：按 glob 模式列出文件路径。
    - 正常返回：匹配的文件路径列表（空列表表示无匹配，不视为错误）。
    - 异常返回：模式非法、目录不存在、权限不足时，返回结构化错误。

  - `search_code`：在指定目录下按正则表达式搜索文件内容。
    - 正常返回：匹配结果列表（文件路径、行号、片段），空列表表示无匹配，不视为错误。
    - 异常返回：正则非法、目录不存在、权限不足时，返回结构化错误。

- **F3: 工具注册中心** — 集中式注册表登记所有可用工具，按名称查找，支持批量导出为 API 所需的工具定义列表（Anthropic 的 `tools` 字段 / OpenAI 的 `functions` 字段）。每次向模型发起对话请求时，将当前注册表中的工具定义一并发送。

- **F4: 工具执行超时** — 每个工具执行带超时控制，超时后干净中断并返回结构化超时错误。分级超时：读/写/改文件 10 秒、搜索 30 秒、命令执行 60 秒。

- **F5: 工具结果结构化返回 + 错误处理** — 工具执行成功返回 `{status: "ok", output: ...}`，失败返回 `{status: "error", error: "具体原因", ...}`。任何工具执行失败（文件不存在、命令超时/非零退出、改文件匹配数不对、搜索无结果等）都以结构化结果回灌给模型，模型可据此调整；同时在 UI 以可区分样式提示。程序不崩溃、会话不中断。

- **F6: 流式工具调用解析** — LLM 客户端在流式输出中解析工具调用（Anthropic 的 `tool_use` / OpenAI 的 `function_call`）。JSON 参数可能分片到达，需要拼接完整后再执行。参数不完整时不提前执行；JSON 解析失败时返回明确错误。

- **F7: 单轮闭环 + 续答** — 模型请求使用工具时，代码执行对应工具，将结构化结果以 `tool_result` / `function` 角色消息追加到对话历史，再次调用模型获取最终文本答复，展示给用户后停止。本章不做连环调用（Agent Loop）：一次回复中只处理一个工具调用，模型拿到结果后生成最终答复即结束。

- **F8: 双协议工具格式支持 + 跨协议一致体验** — Anthropic 协议使用 `tool_use` / `tool_result` 消息格式；OpenAI 协议使用 `function_call` / `function` 消息格式。Provider 层内部处理差异，上层（TUI/单次调用）无感知。工具调用的触发、UI 展示、结果回灌、错误反馈，在两种协议下行为一致。

- **F9: TUI 工具行展示** — 在对话区以可区分的"工具行"展示每次工具调用：工具名 + 关键参数（如 `● Read(path="main.py")`、`● Bash(cmd="ls -la")`），其后展示结果摘要；结果过长时截断/摘要呈现。工具行随流式实时出现，并纳入 scrollback 历史。

- **F10: 单次调用与 TUI 都支持工具** — 单次调用模式（`newcode -c`）和 TUI 模式都能完整走通"提问 → 工具调用 → 结果回灌 → 最终回复"的流程。

- **F11: 改文件唯一匹配** — `edit_file` 的 `old_string` 在目标文件中必须恰好出现一次，否则明确报错（"未找到"或"找到 N 处，无法确定替换哪一处"），让模型调整参数后重试。

## 非功能需求

- **N1: 超时可控** — 工具执行在超时后干净中断，不残留子进程或锁文件。超时即终止该工具并返回超时结果，界面不冻结、会话不挂死。

- **N2: 界面不阻塞** — 工具执行与流式期间界面保持响应（可滚动、可见进行中指示），不冻结（沿用 ch02 N1）。

- **N3: 错误可恢复** — 任何工具执行失败都返回结构化错误，不抛未处理异常，不中断整个会话。

- **N4: 安全沙箱** — 命令执行采用白名单机制，拒绝不在白名单的命令；白名单外的命令直接返回错误，不弹窗询问。

- **N5: 文件操作安全** — 读/写/改文件操作在出现路径越界（如 `../../etc/passwd`）时拒绝执行，限制在项目工作目录内。

- **N6: 流式解析健壮** — 工具调用的 JSON 参数分片到达时正确拼接，参数不完整时不提前执行；JSON 解析失败时返回明确错误。

- **N7: 跨协议一致体验** — 工具调用的触发、UI 展示、结果回灌、错误反馈，在 Anthropic 与 OpenAI 两种协议下行为一致（沿用并扩展 ch02 N3）。

- **N8: 结果体量控制** — 大文件/长输出有上限或截断（读文件行数上限、命令输出截断、搜索结果条数上限），避免撑爆上下文或界面。

- **N9: 与现有架构兼容** — 工具系统作为独立模块接入，不改现有 Provider 协议、ConversationManager、TUI 状态机的核心结构。

- **N10: 路径处理健壮** — 支持相对路径和绝对路径，统一解析为绝对路径后操作，符号链接正确处理。

- **N11: 密钥安全** — API 密钥不回显、不打印到对话区或任何输出中（沿用 ch02 N5）。

## 不做的事

- **Agent Loop / 多工具连环调用 / 自动循环判断**：模型拿到一次工具结果就结束，不自动决定"还需要另一个工具"。
- **交互式命令执行**：命令执行是批量的（给完整命令，返回完整输出），不支持 `vim`、`nano` 等交互式 TUI 程序。
- **并行工具执行**：一次只执行一个工具，不并行。
- **文件系统监控 / 自动刷新**：工具不监听文件变化。
- **网络请求工具（HTTP 调用等）**：ch03 聚焦本地文件和命令。
- **权限系统**：工具执行（含写文件、执行命令）本章不做授权确认，白名单已是唯一安全机制。
- **工具调用中断 / 取消**：本章不支持中途取消正在执行的工具或正在进行的回复（沿用 ch02）。
- **工具调用与结果持久化**：工具调用与结果不落盘，退出即丢（沿用 ch02）。
- **工具行的折叠 / 展开交互**：UI 仅展示工具行 + 结果摘要，不做可交互折叠或详情展开。
- **配置化工具集 / 自定义工具**：工具集固定为这六个，不支持运行时增删或通过配置开关启停。
- **超时时长配置化**：超时为内置合理默认值，本章不通过配置调整。
- **多模态工具结果**：工具结果均为文本，不含图片等非文本产物。
- **并行工具的并发执行优化**：一次回复中的多个工具调用按顺序执行即可，本章不追求并发加速。

## 验收标准

- **AC1**: 用户输入"读取 main.py 的前 10 行"，TUI 对话区出现 `● Read(path="main.py")` 工具行，模型调用 `read_file` 后展示结果摘要，最终回复包含 main.py 前 10 行内容。
- **AC2**: 用户输入"创建一个 hello.py 写入 print('hello')"，TUI 出现 `● Write(path="hello.py")` 工具行，文件被正确创建，最终回复确认创建成功。
- **AC3**: 用户输入"把 main.py 里的 import os 改成 import sys"，模型调用 `edit_file`；当 `import os` 在文件中恰好出现一次时成功替换；未找到或找到多处时，对话区以可区分样式展示明确错误，结构化错误回灌模型，模型可调整重试。
- **AC4**: 白名单命令（如 `ls`、`git status`、`python --version`）能正常执行，TUI 展示 `● Bash(cmd="...")` 及结果摘要；非白名单命令（如 `rm -rf /`、`curl`）被直接拒绝，TUI 展示拒绝信息，结构化错误回灌模型。
- **AC5**: 执行超时命令（如 `sleep 100`）后被中断，返回超时错误（含已收集的部分输出），TUI 展示超时提示，不残留进程。
- **AC6**: 用户输入"列出所有 py 文件"，模型调用 `list_files`，返回项目内所有 `.py` 文件路径列表；无匹配时返回空列表，不报错。
- **AC7**: 用户输入"搜索项目里所有 TODO"，模型调用 `search_code`，返回包含 TODO 的文件路径、行号和片段；无匹配时返回空列表，不报错。
- **AC8**: 工具执行失败时（如读取不存在的文件、命令 exit_code 非 0），对话区以可区分样式展示错误摘要，结构化错误作为消息回灌模型，程序不退出，对话历史保留，模型能基于错误信息调整并继续。
- **AC9**: 单次调用模式 `newcode -c "读取 README.md"` 能完整走通工具调用闭环，终端输出工具行及最终回复后退出。
- **AC10**: TUI 模式下工具调用过程中，界面显示工具执行状态（工具行实时出现），不冻结，可滚动。
- **AC11**: 使用 Anthropic provider 时，工具调用走 `tool_use` / `tool_result` 格式；使用 OpenAI provider 时，走 `function_call` / `function` 格式；两种协议下 TUI 展示、结果回灌、错误反馈行为一致。
- **AC12**: 新增一个工具只需实现统一接口并在注册中心登记，无需修改 Provider 或 TUI 代码。
- **AC13**: 读取超过行数上限的文件时，返回截断后的内容 + 截断提示，不撑爆上下文。
- **AC14**: 命令输出超过长度上限时，返回截断后的输出 + 截断提示。
- **AC15**: 模型调用工具后，最终文本答复正确出现在对话区，工具行与最终答复均纳入 scrollback 历史。
