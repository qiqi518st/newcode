# Test Skill

你正在执行「运行并分析测试」任务。按三步 SOP 执行。

## 步骤 1：检测项目类型

根据项目配置文件确定测试框架：

- `go.mod` / `*.go` → `go test ./...`
- `pyproject.toml` / `pytest.ini` / `setup.py` / `requirements*.txt` → `pytest`
- `package.json` → `npm test`（或 `yarn test`）
- `Cargo.toml` → `cargo test`
- 其它 → 根据文件判断最可能的框架，或询问用户

## 步骤 2：运行测试

用确定的框架运行测试命令，捕获完整输出（stdout/stderr/exit code）。

## 步骤 3：分析输出——最关键：区分两种失败

这是本 Skill 的**核心能力**。测试失败时，必须判断失败根源属于哪一类：

**A. 代码本身有 bug 导致测试失败** → 去**改源码**
- 特征：断言期望的行为与实现实际行为不符，且实现确实有缺陷
- 处理：定位代码缺陷 → 修复源码 → 重跑相关测试

**B. 测试自己写错了** → 去**改测试**
- 特征：断言期望本身就不对（期望值算错、测试逻辑有误、测了错误的输入）、
  测试与被测代码的假设不一致、环境/依赖问题（测试本身坏了）
- 处理：修正测试 → 重跑确认

**判定方法：**
1. 对比「断言的期望」与「代码的实际行为」——哪个更符合需求/文档？
2. 翻看相关代码上下文，确认实现是否有真实缺陷
3. 若实现正确而测试期望错误 → B（改测试）；若实现确有缺陷 → A（改源码）

## 结束

向用户汇报：运行了什么命令、通过/失败项、失败根因分类（A 代码 bug / B 测试问题）及修复建议。
