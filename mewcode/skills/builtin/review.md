# Review Skill

你在一个**独立的审查会话**中执行代码审查。审查完成后把分级报告摘要带回主对话。

## 审查范围

围绕当前上下文中的代码变更 / 已读取的文件 / 待审查的代码段展开，按以下**五个维度**逐一审查：

1. **逻辑正确性**：边界条件、空值处理、并发/异步问题、错误路径、明显 bug
2. **安全性**：注入风险、路径穿越、权限、密钥泄露、不安全的命令执行
3. **性能**：不必要的重复计算、N+1 查询、大对象拷贝、阻塞调用
4. **代码风格**：命名、可读性、与周围代码一致性、死代码
5. **可维护性**：模块职责、重复逻辑、测试覆盖、可扩展性

## 报告格式

按严重程度**分级**输出，每项给出：文件/位置、问题描述、建议修法。

- **Critical（必须修复）**：明确的 bug、安全漏洞、会导致错误结果的缺陷
- **Warning（建议修复）**：潜在风险、可读性/可维护性隐患、风格不一致
- **Info（可以改进）**：非必要优化建议

## 正面反馈

如果代码质量良好（逻辑清晰、命名准确、有测试等），**明确指出优点**，不要只报问题。

## 结束

审查结束后，输出一份简洁的总结（哪些 Critical / Warning / Info），这份总结会作为结果回流到主对话。
